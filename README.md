# RepoGloss

GitHub の英語表示はそのままに、Git / GitHub 固有の用語の右へ小さな ⓘ を付ける Chrome 拡張です。ⓘ にカーソルを乗せると、日本語の説明が出ます。

![License](https://img.shields.io/badge/license-MIT-lightgrey)
![Manifest](https://img.shields.io/badge/manifest-v3-green)

---

## 何をするか

- `github.com` のページで、辞書にある **61 語**の右に ⓘ が付きます
- ⓘ にカーソルを乗せると、日本語の説明がすぐに出ます
- 画面右下のボタンで ON / OFF を切り替えられます（設定は保存されます）

## 何をしないか

- **英語を日本語に置き換えません。** 英語はそのまま残ります
- **コードの中身には印を付けません**（`<pre>` `<code>` と、GitHub の現行コードビューアを除外しています）
- `github.com` 以外のサイトでは動きません
- 外部への通信を一切行いません

---

## 収録している語

61 語です。GitHub が画面を変えても意味が変わらない、Git / GitHub 固有の概念語だけを入れています。

`view all` のような画面のラベルや、`on` `open` `code` のような普通の英単語は入れていません。無関係な箇所に印が付くうえ、GitHub が画面を変えるたびに古くなるからです。

取り返しのつかない操作は、**何を失うか**を書いています。

| 語 | 説明の要点 |
|---|---|
| `reset` | やり方によっては、まだ記録に残していない編集内容が完全に消えること |
| `revert` | 打ち消す記録を後ろに足す方式で、前の記録は消えないこと（`reset` との違い） |
| `token` | 漏れると、許した範囲の操作を他人が本人として行えること |
| `ssh key` | 秘密の鍵が漏れると、他人が本人の名前でコードを書き換えられること |
| `force push` | 他の人の記録が消えて元に戻せなくなることがあること |

辞書の実体は [`locales/dict.json`](./locales/dict.json) です。

### 手動で読み込む

1. このリポジトリを clone するか、ZIP でダウンロードして展開します
2. Chrome で `chrome://extensions/` を開き、右上の **デベロッパー モード** を ON にします
3. **「パッケージ化されていない拡張機能を読み込む」** から、展開したフォルダを選びます
4. `github.com` を再読み込みします

## プライバシー

- 外部への送信は一切ありません。外部サーバーとの通信を行いません
- `github.com` のページ上の文章を読み取りますが、同梱辞書との照合にのみ使い、端末の外へ出しません。保存もしません
- 保存するのは ON / OFF の設定（真偽値ひとつ）だけで、`chrome.storage.local` に置きます
- 要求する権限は `storage` のみ。`host_permissions` `tabs` `activeTab` `scripting` は要求しません

詳細は [PRIVACY.md](./PRIVACY.md) をご覧ください。

- **ツールチップの見え方・出る速さ・位置**（v1.6.1 で自前描画へ変えましたが、目視できていません）

## 辞書を増やす・直す

[`locales/dict.json`](./locales/dict.json) に `"英語キー": "日本語の説明"` を追記し、`chrome://extensions/` で更新を押すだけです。キーは小文字で書いてください。単数形で書けば複数形（`-s` `-es` `-y → -ies`）は自動で拾います。

説明を書くときの方針:

- **何をするものか＋なぜそうするのか** を両方書く。言い換えだけで終わらせない
- 説明の中で `リポジトリ` `ブランチ` `マージ` などを噛み砕かずに使わない
- 1〜2 文、全角 60〜110 字程度
- 取り返しのつかない操作は、何を失うかを必ず書く
- 画面のラベルではなく**概念**を説明する

誤訳の指摘や語の追加は Issue / Pull request でお願いします。

### 1.6.1 の修正について

v1.6.0 まで、印に `U+1F6C8`（CIRCLED INFORMATION SOURCE）という文字を使っていました。この文字は Windows の Segoe UI Symbol には収録されていますが、**macOS の標準フォントには収録されていません。**そのため Mac では豆腐（□）として表示され、印の意味を成していませんでした。

原因は、開発が Windows 環境で行われ、**表示を目で確かめないまま進んだこと**です。JSON の妥当性や正規表現の挙動は自動で検証していましたが、「実際に見えるか」だけ検証していませんでした。

v1.6.1 では、文字コードの記号に頼るのをやめ、**CSS で丸を描き、どのフォントにもある ASCII の `i` を中に置く**方式へ変えました。フォントに左右されません。

`::after` の生成内容は DOM のテキストではないため、本文をコピーしても印は混ざらないはずですが、**これは仕様からの推測で、実測していません。**

あわせて、変更のたびに描画を目視してから出すことにしています。ただし後述のとおり、v1.6.1 のツールチップ変更については目視できていません。
