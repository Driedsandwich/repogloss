# RepoGloss

GitHub の英語表示はそのままに、**Git / GitHub 固有の用語だけ**に 🛈 を添えて日本語の説明を出す Chrome 拡張です。

![License](https://img.shields.io/badge/license-MIT-lightgrey)
![Manifest](https://img.shields.io/badge/manifest-v3-green)

---

## これは何か

GitHub を初めて触ると、`fork` `rebase` `squash merge` `upstream` といった語で手が止まります。困るのは英語そのものより、**その語が何を指していて、なぜその操作をするのかが分からない**ことです。

RepoGloss は英語を日本語に置き換えません。英語はそのまま残し、**傍らに意味を添えます**。英語 UI に慣れながら読み進められるようにするためです。

```
Pull requests 🛈     ← 🛈 にカーソルを乗せると
                        「自分が加えた変更を、相手の作業へ取り込んでもらうための
                         お願いです。取り込む前に内容を見せて相談できます」
```

**対象**: GitHub を使い始めた学生・非エンジニア・文系出身の研究者や実務者。

## 収録している語について

**61 語だけ**を収録しています。少ないのは意図的です。

以前の版は 151 語を収録していましたが、その内訳を調べたところ、この拡張にしか出せない価値がある語は 37% しかありませんでした。

| 除いたもの | 数 | 例 | 理由 |
|---|---|---|---|
| 画面のラベル | 37 | `view all` `your profile` `set up in desktop` | GitHub が画面を変えると意味を失う |
| 普通の英単語 | 44 | `on` `off` `new` `open` `code` `save` `search` | 英文のいたるところに出るため、無関係な箇所に 🛈 が刺さる |
| 一般的な IT 用語 | 10 | `api` `https` `markdown` | 英和辞書で足りる |
| 構造的に当たらない語 | 4 | `-u` `.gitignore` `branch -M` | 単語の区切り判定に引っかからず、そもそも機能していなかった |

残したのは **Git / GitHub 固有の概念語** だけです。`fork` `rebase` `upstream` `force push` のような語は、GitHub が画面を変えても意味が変わりません。

これは「更新が止まっても壊れない辞書」を選んだということでもあります。画面のラベルを追いかける設計にすると、追いかけるのをやめた瞬間に古い訳を出す拡張になります。

実測: `github.com/octocat/Hello-World` の表示テキストに対する検出は **107 箇所 → 65 箇所**。減った分はすべて誤検出でした。

### 特に注意して書いた語

取り返しのつかない操作は、**何を失うか**を書いています。

| 語 | 説明の要点 |
|---|---|
| `reset` | やり方によっては、まだ記録に残していない編集内容が完全に消えること |
| `revert` | 打ち消す記録を後ろに足す方式で、前の記録は消えないこと（`reset` との決定的な違い） |
| `token` | 漏れると、許した範囲の操作を他人が本人として行えること |
| `ssh key` | 秘密の鍵が漏れると、他人が本人の名前でコードを書き換えられること |
| `force push` | 他の人の記録が消えて元に戻せなくなることがあること |

## 使い方

1. インストールして `github.com` を開くと、対象の語に 🛈 が付きます
2. 🛈 にカーソルを乗せると説明が出ます
3. 画面右下の **「意訳 ON / OFF」** ボタンで切り替えられます（設定は保存されます）

> 文章をコピーしたときに 🛈 が混ざる場合は、OFF にしてからコピーしてください。

### 手動で読み込む

1. このリポジトリを clone するか、ZIP でダウンロードして展開します
2. Chrome で `chrome://extensions/` を開き、右上の **デベロッパーモード** を ON にします
3. **「パッケージ化されていない拡張機能を読み込む」** から、展開したフォルダを選びます
4. `github.com` を再読み込みすると 🛈 が出ます

## プライバシー

- **外部への送信は一切ありません。** 外部サーバーとの通信を行いません
- `github.com` のページ上の文章を読み取りますが、**同梱辞書との照合にのみ使い、端末の外へ出しません**。保存もしません
- 保存するのは ON / OFF の設定（真偽値ひとつ）だけで、`chrome.storage.local` に置きます
- 要求する権限は `storage` のみ。`host_permissions` `tabs` `activeTab` `scripting` は要求しません

詳細は [PRIVACY.md](./PRIVACY.md) をご覧ください。

## 辞書を増やす・直す

`locales/dict.json` に `"英語キー": "日本語の説明"` を追記して、`chrome://extensions/` で更新を押すだけです。キーは小文字で書いてください。単数形で書けば複数形（`-s` `-es` `-y → -ies`）は自動で拾います。

説明を書くときの方針:

- **何をするものか＋なぜそうするのか** を両方書く。言い換えだけで終わらせない
- 説明の中で `リポジトリ` `ブランチ` `マージ` などを噛み砕かずに使わない
- 1〜2 文、全角 60〜110 字程度
- 取り返しのつかない操作は、何を失うかを必ず書く
- 画面のラベルではなく **概念** を説明する

誤訳の指摘や語の追加は Issue / Pull request でお願いします。

## 仕組み

- 辞書のキーを **長い順** に並べて正規表現を組みます。`pull` が `pull request` より先にあると「Pull requests」に `pull` の説明が付いてしまうためです
- 単数形・複数形の揺れを吸収します。GitHub の画面は複数形が多く、これが無いと最も目立つタブで当たりません
- 一つの文の中の **すべての一致** に 🛈 を付けます（後ろから順に分割して挿入します）
- `<pre>` `<code>` に加えて、現行の React 版コードビューア（`.react-code-lines` `.cm-editor` など）も除外します。コード本文に説明が刺さらないようにするためです
- 画面遷移で差し替わった部分も監視します
