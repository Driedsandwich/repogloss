## 1. 指摘ごとの対応

### RG-11-01 — 見え方の合図で、まだ印の無い語を探していなかった（P1）

**実測（v1.8.9）**、4通りとも「その語は画面に出ているのに、印は0個」だった。比較のため、最初から見えている別の語（`repository`）には印が付いている。

| 何をしたか | v1.8.9 | v1.8.10 |
|---|---|---|
| 画面幅 1000→500 で現れる | 印 **0** | 印 1 |
| `<head>` の stylesheet を外して現れる | 印 **0** | 印 1 |
| 遷移が終わって不透明になる | 印 **0** | 印 1 |
| `checked` を書いて現れる（5.5秒待つ） | 印 **0** | 印 1 |

**原因。** 合図（遷移・画面幅・`<head>`・操作・暇なとき）はどれも `schedule({deep:true})` を予約するだけで、`runBatch` が全体を走るのは「記録が退役したとき」か「URL が変わったとき」に限られていた。走査し直す場所も退役も無ければ、何も走らない。

**直し方。** 辞書には当たったがそのとき見えていなかった節点を控えておき（`latent`）、見え方が変わったときに**そこだけ**を見直す（`discoverLatent`）。全体走査はしないので費用に上限がある。

見直す前に、**文字列の照合だけで足切り**する。印は1語につき1つなので、既に読める印がある語しか入っていない節点は、見えるようになっても何も足せない。控えからは外さない——その印があとで退役すれば、また候補に戻るからである。

印が0件のときも、控えがあるなら暇なときの確認を止めない（`glossed.size === 0 && latent.size === 0`）。控えは2,000件を上限とし、超えたら全体走査へ落とす。

**証拠。** E2E — 4通りとも印が1個付くこと。既に読める同じ語があるときは増えないこと。合図を100回まとめても印が増えないこと。

### RG-11-02 — 退役で所有を取り消さず、合言葉も不変条件でなかった（P2 相当の実害を伴う P1）

**実測（v1.8.9）**、4通りとも再現した。

| 何をしたか | v1.8.9 | v1.8.10 |
|---|---|---|
| 生きた正規の印から合言葉を外す | 幅0・`role=button`・`tabindex=0` が残り、後ろは0個 | 古い印は消え、**見える印1個**に置き換わる |
| 退役した領域をページが DOM へ戻す | 同じ語の押せる印が **2個** | **1個** |
| 複製の合言葉を別の値へ書き換える | 複製も印として描かれ、合計 **2個** | 複製は取り除かれ **1個** |
| 複製から合言葉を消す | 幅0のまま **Tab の停止点**として残る | 取り除かれ、停止点は増えない |

**原因。** `retireGloss()` が `ownedIcons` から所有を取り消していなかった。`isCoherent()` も合言葉の値を要求していなかった。複製の判定が `[data-iiyaku-owner="UID"]` という**値の一致**だったので、値を変えた複製も消した複製もすり抜けた。

**直し方。**

1. 退役の時点で `ownedIcons` / `iconTrigger` / `expectedAttrs` から取り消す。
2. `isCoherent()` に「`ownedIcons` にあること」と「合言葉が現在の値と一致すること」を足す。
3. 複製の判定を、**自分が書いた説明文そのもの**に変える（辞書のキーと、そのキーの説明文が一致していること）。ページ側が同じ class を使っているだけの要素には当たらない。
4. 見た目の側も、走り出しに規則を1つ足して合言葉の**値**まで見る。消すのではなく与えないだけなので、ページ側の要素を壊さない。

「自分が作ったか」と「いま自分の正規の印か」を別の集合に分けた（`madeIcons` と `ownedIcons`）。分けないと、所有を取り消した印を DOM から外す動作が「ページが起こした変更」に見え、余計なまとめ直しを呼ぶ。

**監査の期待と1点だけ違う。** 合言葉を外された場合、監査は「後ろの第2候補へ移る」ことを期待していた。実測では**元の場所へ付け直される**。その場所はいまも読めるからで、後ろへ譲る理由がない。受入条件の実質（**見えない停止点が0**・印が増えない）は満たしている。

**証拠。** E2E — 上の4通り。加えて、ページ側の同名 class 要素（`class="iiyaku-icon" data-iiyaku-owner="page"`）を消しも書き換えもしないこと、その要素が印として描かれないこと、複製を足しても Tab の停止点が増えないこと。

### RG-11-03 — 吹き出しと切替ボタンを class 名で見分けていた（P2）

**実測（v1.8.9）**、影響は2つに分かれた。**片方は永久に残り、もう片方は遅れて直る。**

| 何をしたか | v1.8.9 | v1.8.10 |
|---|---|---|
| ページ側の本文が `class="iiyaku-tooltip"` を名乗る | その中を**永久に走査しない**（語は後ろの段落へ回る） | ふつうに走査して、その場に印が付く |
| ページが自分の段落へ同 class を付けてから隠す | **1,876 ms 後**に後ろへ移る（暇なときの確認で拾う） | **141 ms** で移る |

**監査の報告との違いを1つ。** 監査は後者を「印がそこに残る」と報告したが、実測では**永久に残るのではなく、次の暇なときの確認まで遅れる**。測った時点では残っているので観測は正しい。

**原因。** `SKIP`・`isSelfMutation()`・`isOurNode()`・CSS が class 名を所有の証明として使っていた。名前は誰でも名乗れる。

**直し方。** `tip` と `toggleBtn` の**要素同一性**で見分ける（`isOurChrome`）。除外一覧から2つの class 名を外し、CSS も合言葉つきの選択子へ寄せた。

### RG-11-04 — 面積0の切り取りを2形取りこぼす（P2）

**実測（v1.8.9）**、どちらも「当たり判定では文字に触れないのに、隠れた側へ印が付き、後ろの可視語は0個」だった。

| 書き方 | computed 値 | v1.8.9 | v1.8.10 |
|---|---|---|---|
| `circle(closest-side at 0 50%)` | `circle(at 0px 50%)` | 隠れた側に印1・後ろ0 | 隠れた側0・**後ろに1** |
| `clip-path: content-box`（content box が0） | `content-box` | 隠れた側に印1・後ろ0 | 隠れた側0・**後ろに1** |

**原因。** 半径を省くと computed 値は `at` から始まるが、引数を `\s+at\s+` で切っていたので、行頭の `at` では切れず半径の側へ丸ごと入っていた。参照ボックスの分離も「前に形があること」を前提にしていた。

**直し方。** 行頭の `at` でも切れるようにし、半径が空なら既定の `closest-side`（中心からいちばん近い辺までの距離）として面積を判定する。参照ボックス単独の指定も受け付け、その箱の幅か高さが 0 以下なら全面が消えると判定する。

**既知の制約は維持**: `calc()` を含む値、`polygon()`、`path()`、`shape()` は解かない（可視として扱う）。

**証拠。** E2E — 上の2形。加えて**対照**として、潰れていない参照ボックス（`padding:10px` の `content-box`）を誤って落とさないこと。

### RG-11-05 — 1回の変更で、まとめ直しが2回走る（P2）

**実測（v1.8.9）**: 1回 `style.display='none'` にすると、予約が **2回**走った。

**原因は監査の見立てと半分違う。** 監査は「自分の印を走査し直す場所へ無条件に入れている」ことを原因としたが、切り分けたところ主因は**本文を割ったこと**だった。語が節点の末尾で終わる形（割らない形）にすると、v1.8.9 でも1回で済む。

| ページの形 | v1.8.9 | v1.8.10 |
|---|---|---|
| 語の後ろに文字がある（割る） | **2回** | 1回 |
| 語で節点が終わる（割らない） | 1回 | 1回 |

**直し方。** 印を1つ入れると DOM には3つの変更が出る——印が増える・右側の節点が増える・左側が短くなる。後ろ2つを「次に1回だけ起きるはず」として控え、受け取った時点で消す（属性の予定表と同じ考え方）。覚えっぱなしにしないのは、そのあとページがその節点を書き換えたときに気づけなくなるため。あわせて、自分の印を走査し直す場所へ入れないようにした（監査の指摘どおり）。

読まれないままだった再入防止の旗（`inBatch`）は削除した。守っているつもりの不変条件が、実際には誰も見ていない状態になるため。

**証拠。** E2E — 1回隠すとまとめ直しは1回。吹き出しを出しただけでは本文の走査を予約しない。数える仕掛け自身が効いていることを、同じ実行の陽性対照で先に確かめる。

### RG-11-06 — 監査入口が対象を「main の先頭」と名乗っていた（P2）

**実測**: `AUDIT.md` は `v1.8.9` = `cea7a295…` を「`main` の先頭」と書いていたが、提出候補の SHA を記録したコミット `105e8b03…` を積んだ時点で、`main` の先頭ではなくなっていた。配布13ファイルに差は無いので動作への影響は無い。

**原因。** **相対的な言い方は、次のコミットで嘘になる。** 私が書いた表現である。

**直し方。** 対象はタグとコミットだけを名乗る。いまの `main` との関係は、**機械で確かめられる形**にした——`state` が `uncommitted` でないとき、`verify` が「AUDIT.md が名乗るタグと、いまの配布13ファイルが同じか」を `git diff` で突き合わせる。タグが引けない環境では**通さない**（「一致していた」と「確かめていない」が同じ見た目になるため）。CI の `checkout` に `fetch-tags` を足した。

**現在の main のコミットは書かない。** 書けば、その値もまた次のコミットで古くなる。

## 5. 未検証・既知の制約

- **Chrome 105〜150 の実機では試していない**（手元は 151 のみ）
- **属性にも DOM にも出ない変化は、即座には拾えない**。2秒ごとの確認でのみ気づく（v1.8.9 から変わらず）
- **`calc()` / `polygon()` / `path()` / `shape()` の `clip-path` は解かない**（可視として扱う）
- **控えの見直しの費用を、実サイトで長時間は測っていない**。合成試験では、隠れた段落が500本ある頁で1回あたり +0.2〜0.3 ms（3組とも同じ向き）

- 実スクリーンリーダーでの確認はしていない
