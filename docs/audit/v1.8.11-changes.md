## 1. 指摘ごとの対応

### RG-12-01 — 控えの見直しが、保護領域の判定より先に本文を読んでいた（P1）

**実測（v1.8.10）**。初回に隠れていた段落を控えたあとで、その段落を**編集中**にしつつ表示へ戻し、本文へ目印を入れると——

```
data-rg-raw: RGSENTINEL_LATENT,RGSENTINEL_SELFTEST
```

目印が記録されました。約2秒ごとの確認のたびに、編集中の本文が読み取られていたことになります（外部送信はありません）。

**原因。** `discoverLatent()` が `node.nodeValue` を取ってから `isTarget()` を呼んでいました。初回走査（`isTarget`）は除外を先に見ているのに、見直しの経路だけ順序が逆でした。**私が第11回で足した足切りの置き場所が誤っていた**ものです。第9回 RG-9-04（記録の確かめ直しが除外判定より前に本文を読む）と同じ型の再発です。

**直し方。** 見直しの順序を、走査の入口と揃えます。

```text
接続しているか → 親があるか → いま触れてよい場所か（inSkip）
→ ここで初めて本文を読む → 辞書で足切り → 見え方 → 注記
```

触れない場所へ移った候補は、読まずに控えから外します。戻ってきたときは、その属性変更が走査し直す場所として渡ってくるので、そこで入り直します。

**証拠。** E2E — 編集中・`aria-hidden`・`inert`・`hidden` の4種へ移した控えの本文を、2秒周期を2回以上通しても**一度も読まない**こと。加えて**陽性対照**として、保護されていない控えは読んで注記すること（読み取りが記録されること）。計装が効いていること自体（`data-rg-rawtap === 'ready'`）も先に確かめます。

### RG-12-02 — 入口がまだ無いだけの語を、永久に処理済みにしていた（P1）

**実測（v1.8.10）**: `<button disabled>branch</button>` は印0。`disabled` を外して5秒待っても**印0のまま**（`tabIndex` は 0 で、ブラウザ上は入口として使える状態）。

**原因。** `annotate()` は `resolvePlacement()` が `skip` を返すと `markHandled(node)` して終わります。この節点は**見えている**ので控えにも入らず、同じ世代では `isTarget()` が即座に弾きます。

**直し方。** 入口が無いのは*いまだけ*かもしれないので、処理済みにせず控えへ入れます。見え方や入口が変わったときに見直します。

**監査の挙げた4例のうち1つは、実装では該当しませんでした。** `href` の無い `<a>` は入口の候補にならないので、その中の語は最初から**ふつうの印**（印自体を入口にする形）で説明されます。試験には対照として残してあります。

**証拠。** E2E — `disabled` を外す／`tabindex` を `-1` から `0` にする／`label` の `for` を後から付ける、の3通りで印が1個付くこと。再び `disabled` にすると退役すること。`href` の無い `<a>` は最初から説明されること（対照）。

### RG-12-03 — 見張る前に走査したため、最初の外部変更を捨てていた（P2）

**実測（v1.8.10）**: 注記の直後に語そのものを消しても、**250 ms 時点では印が動かず**、2,850 ms 時点でようやく後ろへ移りました（暇なときの確認で回復）。

**原因。** 初回走査は `observer.observe()` より**前**に走ります。本文を割ったときに登録する「次に1回だけ起きるはず」の予定が、対応する変更を観測されないまま残り、**そのあとページが起こした最初の文字変更を消費**していました。

**直し方。** 見張り始めてから走査します。これで、走査中に自分が起こす変更は必ず観測され、予定はその場で消費されます。

**証拠。** E2E — 予約の回数を数える計装を使い、最初の外部の文字変更で**その場で1回**まとめ直しが走ること（0 なら捨てている）。印も同時に後ろへ移ること。

### RG-12-04 — 控えの上限で、探すのをやめてしまう（P2）

**実測（v1.8.10）**。控えの中身を直接測ったところ、境界は監査の報告と少し違いました。

| 隠れた候補の数 | 控えの状態 | property だけの表示変化を拾うか |
|---|---|---|
| 1,998（＋対象1＝計1,999） | `latent 1999 / overflow false` | 拾う（印1） |
| 1,999（＋対象1＝計2,000） | `latent 0 / overflow true` | **拾わない（印0）** |
| 2,001 | `latent 0 / overflow true` | **拾わない（印0）** |

**原因は上限そのものより、数え方でした。** `rememberLatent()` が**既に控えてある節点かどうかを見ずに**上限と比べていたため、見直しのたびに数え直して上限へ達し、控えを丸ごと捨てていました。捨てたあとは「候補0件」に見えるので、暇なときの確認が先へ進まず、二度と探しません。

**直し方。**

1. 既に控えてあるものは数えない（`latent.has(node)`）。
2. 上限に達しても**捨てない**。増やすのをやめるだけにする。捨てると「もう探さない」に化けます。
3. 上限は 20,000 へ。超えた分は全体走査（退役・画面遷移・ON 復帰）でのみ拾う、と文書に明記。

**証拠。** E2E — 隠れた候補2,100件（旧上限超え）のページで、property だけの表示変化を拾うこと。

### RG-12-05 — 参照ボックスが「潰れている」ことと「分からない」ことを混ぜていた（P2）

**実測（v1.8.10）**: `clip-path: inset(0) content-box` を content box 0×0 の要素へ掛けると、当たり判定では文字に触れない（`BODY` が返る）のに、隠れた側に印1・後ろの読める語は0でした。

**原因。** `insetClipsAll()` の `useBox` が `w > 0 && h > 0` を要求していたため、既知の 0 と寸法不明（`null`）が同じ経路へ落ちていました。面積の式そのもの（`top + bottom >= bh`）は 0 でも正しく働きます。

**直し方。** 寸法が**分かっているか**で分けます（`Number.isFinite(w) && w >= 0`）。負の inset で外へ広がる形も、同じ式で正しく可視と出ます。

**証拠。** E2E — 0×0 の content box ＋ `inset(0)` で隠れた側0・後ろ1。**対照**として、負の inset（`inset(-20px)`）と、潰れていない content box（`padding:10px`）は誤って落とさないこと。

### RG-12-06 — class 名の衝突が2か所に残っていた（P2）

**実測（v1.8.10）**、2つとも再現しました。

| 何をしたか | v1.8.10 | v1.8.11 |
|---|---|---|
| ページ本文が `class="iiyaku-icon"` を名乗る | その中を**一度も走査しない**（印0） | ふつうに走査する（印1） |
| 本物の説明を出した状態で、ページ側の `.iiyaku-tooltip` へポインタを移す | **閉じない** | 閉じる |

**原因。** 除外一覧に `.iiyaku-icon` が残っており、カーソル位置の判定も `closest('.iiyaku-tooltip')` でした。第11回で吹き出しと切替ボタンの主要な判定は要素同一性へ移しましたが、この2か所が残っていました。

**直し方。** 除外一覧から class 名を外し、自分の印は要素同一性（`madeIconAt`）で除きます。吹き出しの中かどうかは、**いま出している吹き出しそのもの**で見ます。

**証拠。** E2E — ページ側の `.iiyaku-icon` 本文がふつうに説明されること。ページ側の `.iiyaku-tooltip` へ移ったら閉じること。**本物の吹き出しへ移ったときは閉じないこと**（長い説明を読めるようにするための挙動。対照）。

## 6. 性能

3つの形で v1.8.10 と比べました（実行順は交互に反転）。

| 何を | v1.8.10 | v1.8.11 | 判定 |
|---|---|---|---|
| 初回走査（3,000段落・8組） | 中央値 12.25 ms | 中央値 13.55 ms | **判定しない**（下記） |
| 属性の切替（2,500段落・3組） | 16.8 / 16.3 / 19.4 ms | 19.0 / 16.4 / 16.4 ms | 差を判定できない（符号が混在） |

**初回走査は「遅くなった」と読みません。** 8組のうち7組で v1.8.11 が遅く出ましたが、値の分布が二峰性で（きれいな値は両版とも約12 ms、時折 20〜30 ms の外れ値が出る）、**新しい判定を丸ごと外した版を並べても同じだけ遅く出ました**。つまりこの増加は版差では説明できません。

控えの費用が下がったのは、除外一覧から選択子が1つ減ったためと考えられます。
