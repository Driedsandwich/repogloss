## 1. RG-13-01（P1）語の実際の描画領域と、祖先の切り取りを照合していない

### 再現（v1.8.11・画素で確認）

| 場面 | 描かれた画素 | 印 | 判定 |
|---|---:|---:|---|
| `overflow: hidden` の枠の外に置いた語 | **0** | 1 | ❌ 見えない語に印 |
| `overflow: clip` の枠の外 | **0** | 1 | ❌ |
| 面積のある `clip-path: inset(0 120px 0 0)` の外 | **0** | 1 | ❌ |
| `filter: opacity(0)` | **0** | 1 | ❌ |
| `transform: scale(0)` | **0** | 1 | ❌ |
| 色がすべて透明な `mask` | **0** | 1 | ❌ |
| 1px の箱＋`clip-path: inset(-100px)`（外へ広がって描かれている） | **362** | 0 | ❌ 読める語を落としている |
| 切り取りに一部だけ掛かっている | 671 | 1 | ○ |
| 何の細工もしない（陽性対照） | 841 | 1 | ○ |

6件は**同じ語が後ろの読める場所にもある**のに、そちらへ説明が回りませんでした。RepoGloss は同じ語をページで1回だけ説明するため、見えない最初の出現に印が付くと、後ろの読める出現が恒久的に抑止されます。

### 直し方

「切り取りの指定が面積0か」を見るのをやめ、**viewport 座標の矩形**で決めます。

- 祖先をさかのぼって、`overflow`（`hidden` / `clip` のみ）・legacy `clip`・`clip-path` が課す切り取りを矩形として積み上げる（`paintChain`）
- 語そのものの矩形（`Range.getClientRects()` の**面積があるものだけ**）と交わるかで決める（`isPaintedText`）
- 交わりが 1px 以下の帯しか残らないなら、読める文字は残らないので不可視とする

これで、これまでの「面積0の切り取り」はすべて特別扱いなしに落ちます（`rect(0 0 0 0)` / `inset(50%)` / `inset(100%)` / `circle(0px)` / 潰れた参照ボックス）。

**落としすぎないための約束も一緒に入れました。**

- `overflow: auto` / `scroll` は**切り取りに数えない**。スクロールすれば読めるので、画面外というだけで永久に除外すると長い一覧の下が説明されなくなる
- **絶対・固定配置は、包含ブロックでない祖先の切り取りから逃げる**（`establishesContainingBlock`）。ここを見ないと、読める語を切り取られたものとして落とす
- 大きさの目安（1px 四方）だけで不可視と決めるのをやめた。上の表の7行目は、この目安が原因だった
- `polygon()` / `path()` / `shape()` / `calc()` は解かず、**断定しないほう（可視）へ倒す**

描画効果は、**断定できるものだけ**を不可視とします——`filter: opacity(0)`（等価な computed 値を含む）と、色がすべて透明な単純なグラデーション mask。`transform: scale(0)` は、文字の矩形に面積を求めることで落ちます（箱の寸法は変わらないので、面積を見ないと落とせません）。

### 直したあと

上の9件すべてで、**画素と印が一致**しました（0画素なら印0、描かれていれば印1）。

## 2. RG-13-02 `:hover` / `:focus-within` だけで短時間ひらく場所

### 再現（v1.8.11）

| | メニューの表示 | 印 |
|---|---|---:|
| カーソルを乗せて 400ms | `block` | **0** |
| 乗せたまま 5,000ms（2秒の確認をまたぐ） | `block` | 1 |

CSS の疑似クラスだけで開くメニューは、DOM も属性も遷移も動かないため、どの合図にも乗りません。2秒ごとの確認より先に閉じるメニューは、一度も説明されませんでした。

### 直し方

`pointerover` / `pointerout` / `focusin` / `focusout` を合図に足しました。ただし、

- **控えが空なら何もしない**（見直す先が無い）
- **1フレームに1回へまとめる**（カーソルは大量に動くため）

直したあと、**400ms のあいだに印が付き**、閉じたあとには見えない印が残りません。

## 3. RG-13-03 複製の判定が辞書の説明文に依存し、ページ側の要素まで消していた

### 再現（v1.8.11）

- 複製から `data-iiyaku-key` を消す／説明文を消す／説明文を書き換える → **どれも生き残り**、幅 14.34px の押せる印として描かれ、`tabindex=0` で Tab の停止点になった
- ページ側の `<span data-iiyaku-key="fetch" data-iiyaku="<辞書の説明文>">PAGE DATA</span>` → **起動時に本文ごと消えた**
- ページ側の `<div class="iiyaku-tooltip" data-iiyaku-owner="page">` → `position: fixed` / `z-index: 2147483647` が乗った（切替ボタンも同様）

### 直し方

**辞書の説明文を所有の証明に使うのをやめました。** 判定は自分の側の証拠だけで行います。

1. 今回の読み込みの合言葉（`data-iiyaku-owner` が現在の UID）を持ち、いま自分の正規の印ではないもの → 自分が作ったものの複製と断定できる。**中身が空なら外し、中身があるなら名札を外すだけ**にする
2. 合言葉を消された／書き換えられた複製 → 断定できないので、`<sup>`・自分の class・**中身が空**・押せる、の4つが揃ったものだけを扱う。自分の名札が1つでも残っていれば名札ごと外し、1つも無ければ**操作性だけ**を外す（class も本文も触らない）
3. ページ側が中身を入れている節点は、どちらの場合も消さない

見た目の絞り込み（`scopeOwnStyle`）を、印だけでなく**吹き出しと切替ボタンにも**広げました。`styles.css` が与える性質と、絞り込みで戻す性質の一覧が食い違わないよう、`verify.mjs` が両者を突き合わせます。絞り込みの規則がページから外された場合は、まとめ直しのたびに足し直します。

## 4. RG-13-04 生成した印の生命周期と意味の照合

### 再現（v1.8.11）

| 場面 | 結果 |
|---|---|
| ページが正規の印だけを外す | 350ms 後も印 **0**。約2秒後の確認まで戻らない |
| 退役した印をページが本文として使い回す | 中の語に印 **0**（その領域が二度と走査されない）。さらに、その節点が**本文ごと消えた** |
| 説明文・用語・`role` を書き換える | 3秒後も `WRONG EXPLANATION` のまま、押せる印として残る |

原因は「**自分が作ったことがある**」という永久の記録（`madeIcons`）を、変更の出どころの証明に使っていたことです。作ったのが自分でも、外したのは相手かもしれません。

### 直し方

- 「作ったことがある」記録を**廃止**しました。変更の出どころは「いま自分のものか（`ownedIcons`）」と、「**自分が外す直前に控えたか**（`expectedRemovals`・1回だけ受け取る）」の2つだけで言います
- 走査から除くのも「いま自分の正規の印」だけにしました（退役した節点はページのものへ戻る）
- `isCoherent` が、記録の**中身と意味**まで確かめます——`<sup>`・class・辞書のキー・説明文・用語・置き方ごとの `role` / `tabindex` / `aria-*`。食い違ったら退役させ、正しい印を作り直します（本文には触れません）
- 退役のとき、その節点にページの中身が入っているなら消さず、名札を外すだけにします

直したあと、外部の削除には**待たずに**戻り（500ms 以内に1個）、使い回された節点は消えずに中の語も説明され、書き換えられた説明は正しいものへ戻ります。

## 5. RG-13-05 属性の予定が消費されない ／ `<html>` が見張られていない

### 再現（v1.8.11）

`<html data-color-mode="dark">` を書いて表示を消したところ、

| | まとめ直しの回数 | 印 |
|---|---:|---:|
| 400ms 後 | **0**（1回も走っていない） | 1（見えないまま残る） |
| 約2秒後（暇なときの確認） | 1 | 0 |
| ［対照］`body` の中の要素の属性を変える | 1 | — |

**症状は指摘のとおりでしたが、原因は「予定が消費されないこと」ではありませんでした。** `observer` は `document.body` と `document.head` しか見ておらず、**`<html>` の属性変更は1件も届いていません**。

### 直し方

- `<html>` の属性も見張ります（子孫は body 側で見ているので `subtree` は付けません）。ただし**走査し直す場所には入れません**——1回の書き換えでページ全体を歩き直すことになるためです（`<head>` の stylesheet と同じ扱い）
- あわせて、指摘された「予定の消費」も直しました。予定を **{変更前, 変更後} の待ち行列**にし、`attributeOldValue` で受け取った変更前の値と突き合わせて**1回だけ**消費します。見張っていないあいだの予定は、切り替えのときに捨てます

直したあと、`<html>` の属性変更に **500ms 以内**で気づき、自分が最後に書いた値へページが戻す変更も外部の変更として扱います。

## 6. RG-13-06 控えの上限と、周期的な長い処理

### 再現（v1.8.11）

| 控えの件数 | 1回の見直し（実測） |
|---:|---|
| 500 | 2.2〜2.7 ms |
| 5,000 | 18.9〜22.3 ms |
| 20,000 | **32.7〜60.6 ms**（2秒ごとに繰り返す） |

境界は、痕跡の残らない見え方の変化（CSSOM で規則を足す）で測ると **20,001 件目だけが見つかりません**でした（19,999 / 20,000 は見つかる）。上限に達したことは `latentTruncated` に記録されますが、**この旗はどこからも読まれていません**でした。

### 直し方

- 見直しを **8ms の予算**で区切り、続きは次へ持ち越します（並びを控えて位置を覚え、マイクロタスクではなく一度ブラウザへ返してから続けます）
- 満杯のときは、まず**死んだ控え**（ページから外れた・処理済み）を落として空きを作ります
- 旗を**実際の入れ直し**へつなぎました。ひと回りし終えたときに旗が立っていて、かつ空きがあるなら索引を作り直します

> ⚠️ 最初に書いたときは、**入れ直す前に旗を下ろして**いました。空きが無くて引き返した1回で旗が消え、あとで空きができても二度と入れ直しません（実測で再現）。旗を下ろすのは実際に入れ直すときだけにしました。

直したあと、20,000 件でも1回 **8.3 ms**（50ms の線から十分下）で、上限からこぼれた候補も**空きができれば見つかります**。

**残る限界**: 控えが一度も減らない頁では、上限を超えた分はなお説明されません。これは §5 の既知の限界に書きました。

## 7. RG-13-07 配布 `DESIGN.md` の既知の限界が現行と食い違う

`DESIGN.md` §5 に、次の2つが残っていました。どちらも現行の実装と反対のことを言っています。

- 「DOM の監視をまとめていない。MutationObserver の呼び出しごとに走査しており」→ 実際は `queueMicrotask` で1つの予約口へまとめている
- 「`characterData` や `hidden` / `aria-hidden` の解除だけで表示された要素は捕捉していない」→ 実際は `characterData: true`・属性は絞り込みなし・控えの見直しもある

§5 を現況（いま解かない切り取り・描画効果の範囲、控えの上限、属性にも DOM にも出ない変化）へ書き直し、いまの仕組みを明記しました。**旧仕様の断定文が戻ると構成検査が落ちます**（陽性対照つき）。
