## 1. RG-19-01（P1）複数語の用語を、一部だけ読める状態でも可視扱いしていた

### 何が起きていたか

語の矩形は空白で切って並びごとに取っていました（第18回 RG-18-02）。しかし判定は `rects.some(...)` で、**どれか1つの並びが読めれば用語全体を可視**としていました。

| 見本 | 実測（v1.8.17） | 印 |
|---|---|---:|
| 幅27pxの `overflow:clip` の中の `pull request` | `pull` 158画素／`request` **0画素**（切り取りの右端 35px） | 1 ❌ |
| その印そのもの | x=93.8（切り取りの外）・`tabIndex:0` で**Tab の順路に入る** | — ❌ |

### 直したこと

`rangeRects` を **`rangeRuns`**（並びごとの配列を返す）へ変え、**全部の並びが読めること**を求めます。1つの並びの中では、折り返した断片のどれか1つが読めれば十分です（折り返しても読めるので）。

### ⚠️ 印の場所は、予測をやめて実物を測る形にしました

最初、印が入る場所を「用語の最後の並びの直後に 1.4em」と見積もって判定へ入れました。**その見積もりが外れました。**

| 見本 | 私の見積もり | 実物の印 |
|---|---|---|
| 35°回した楕円の**中**の語（`merge`） | 形の外＝落とす | (60.7, 83.7) 5×5・**5点中4点が印に当たる**＝見えている |

見積もりで落とすと、読める語まで説明されなくなります（既存の対照が4件落ちました）。いまは**入れてから実物を測り**、描かれていなければ引き取って控えへ戻します（`iconIsPainted`）。

### そのとき、既存の見えない停止点が2つ見つかりました

同じ物差しを当てると、**v1.8.17 が作っていた見えない停止点**が実測で出ました。

| 見本 | 語 | 印 | 5点の当たり判定 |
|---|---|---|---|
| `clip-path:inset(-60px) content-box`（0×0 の content box を負の inset で広げる） | 読める | (117.1, 80.2) 14.3×14.3 | **5点すべて BODY**＝描かれていない |
| `overflow:clip; overflow-clip-margin:100px` | 読める（余白の中） | (176.3, 33.9) 10.8×10.8 | **5点すべて DIV**＝描かれていない |

どちらも `tabIndex:0` で Tab の順路に入っていました。**この2件を固定していた既存の対照（RG-12-05・RG-16-07）は、期待値のほうを書き直しました**——見えない停止点を正しい振る舞いとして固定していたためです。直したあとは、印が引き取られ、Tab の順路からも消えます（実測: `["after","BUTTON","BODY","before"]` に SUP が出てこない）。

## 2. RG-19-02（P1）吸い寄せで止まれない位置を、到達可能とみなしていた

### 何が起きていたか

到達可能性は「連続した区間のどこへでも動かせる」として解いていました。`scroll-snap-type: x mandatory` では、有効な止まり位置があるかぎりブラウザがそこへ吸い寄せるので、**途中の位置では止まれません**。

```text
要求 0 / 50 / 100 / 150 / 200  → 実効 0
要求 250 / 300 / 350 / 400 / 401 → 実効 401
```

語は `left:200px`、枠の幅は 100px。**どちらの止まり位置でも読めない**のに、印が付いていました。

### 直したこと

枠ごとに「吸い寄せのある軸」を持ち（`snapAxes`）、`reachable` を三値にしました。

1. 吸い寄せのある枠を**いまの位置に固定**して解く → 入れば `true`（いま見えている）
2. 入らなければ、連続区間で解く → 入れば **`unknown`**（止まり位置は解かない）／入らなければ `false`

止まり位置そのものは解きません。代わりに、**スクロールが落ち着いたら控えを見直します**（`scrollend`。無い版では `scroll` から 150ms 遅らせて1回）。

論理軸（`block` / `inline`）は書字方向から物理軸へ写します。

## 3. RG-19-03（P1）変形前へ戻せない角度で、広い形を可視の根拠にしていた

外接矩形の寸法から元の箱を復元する式は、`|a||d| = |b||c|`（ちょうど45°など）で不定になります。そのとき **viewport の外接矩形の4隅を逆写像した平行四辺形**へ落としていましたが、これは実際の文字より大きく、形の外の語まで拾います。

| 見本 | 実測（v1.8.17） | 印 |
|---|---|---:|
| `rotate(45deg)` ＋ `ellipse(50px 20px)` の**外**の語 | 0画素・5点すべての hit test が **BODY** | 1 ❌ |

**`backPoly` は `null` を返す**ようにし、形の判定を三値（`true` / `false` / `'unknown'`）にしました。断定できない形は可視へ昇格させず、後ろに確実に読める同じ語があればそちらへ付けます。

対照として **44.9°** を置いています（解けるので、形の外は落とせて、形の中は付く）。

## 4. RG-19-04（P1）`background-size:auto` の画像を、領域いっぱいとみなしていた

`auto` は置換画像の**自然寸法**を使います。領域全体の寸法で塗る箱を作っていたため、1×1 の画像を `no-repeat` で置いただけの段落を「語の位置まで塗る」と答えていました（実測: 語の画素は 0 なのに印 1）。

自然寸法は**同期では分かりません**。読みに行けば新しい通信になるので（この拡張は同梱物以外を一切取りに行きません）、**断定せず `unknown`** にしました。gradient の `auto` は領域いっぱいなので、そちらは今までどおり解きます。

| 見本 | 前 | 後 |
|---|---:|---:|
| 1×1 の画像・`no-repeat`・`auto` | 1 ❌ | **0**（後方へ譲る） |
| ［対照］同じ画像を `repeat` | 1 | 1 |
| ［対照］gradient の `auto` | 1 | 1 |

## 5. RG-19-05（P1）解けない `filter` の `url()` と `mask-mode:luminance`

### filter

`url()` を見たら、それまでの「透明」の断定を捨てて**可視へ戻して**いました。SVG の filter は `SourceGraphic` 以外を入力にでき、出力は何にでもなります——完全に透明にもできます。

| 見本 | 実測（v1.8.17） | 印 |
|---|---|---:|
| `filter: url(#f)`（中身は `feFlood flood-opacity="0"`） | 0画素 | 1 ❌ |

`filterState` を三値にしました。`opacity(0)` は確実に 0、`url()` は**断定できない**、その他は断定を変えない。最後まで見て決めます。`opacity(0) url(#f) opacity(0)` が `hidden` になることは変わりません。

### mask

`mask-mode` を見ていませんでした。`luminance` では色の**明るさ**が覆いの値になるので、**黒は 0＝完全に消えます**。

| 見本 | 実測（v1.8.17） | 印 |
|---|---|---:|
| `mask-image: linear-gradient(black,black); mask-mode: luminance` | 0画素 | 1 ❌ |
| ［対照］同じ層で `mask-mode: alpha` | 描かれる | 1 ○ |
| ［対照］`linear-gradient(white,white)` ＋ `luminance` | 描かれる | 1 ○ |

層ごとに `mask-mode` を見て、明るさを色から出します（`0.2126R + 0.7152G + 0.0722B`、alpha 0 は 0）。画像の明るさは解けないので `unknown`。

## 6. RG-19-06（P2）固定のレイヤー名を、ページが狙って先に宣言できた（3巡持ち越しの解消）

### 実物での観測は、監査と**向きが違いました**

監査の報告では「ページ所有要素が拡張の見た目へ**置き換わる**」（`display:grid → inline-flex`・`140px → 14.34px`・赤 → 拡張の青）でした。**拡張として実際に読み込むと、そうはなりません。**

| 見本（ページが `@layer repogloss-e7b41d-scope, repogloss-e7b41d;` を先に宣言） | v1.8.17 の実測 |
|---|---|
| `display` | grid → **inline**（UA 既定） |
| `color` | rgb(255,0,0) → **rgb(0,0,0)** |
| `width` / `height` | 140px / 30px → **auto** / **auto** |

原因は、走り出しに入れていた絞り込みの規則が `revert` を使っていたことです。`revert` は**author origin ごと**巻き戻すので、ページがこちらのレイヤー名を使って書いた指定も一緒に消えます。監査側のプローブは isolated world へ CSS を素の author style として入れているため、カスケードの位置が実物と違って見えたのだと思われます。**害は同じ**（ページ自身の指定が消える）で、指摘は成立します。

### 直したこと

**見た目を走り出しに読み込む形へ作り替えました。**

| | v1.8.17 | v1.8.18 |
|---|---|---|
| `styles.css` の入り方 | `manifest.json` の `content_scripts.css`（静的） | `web_accessible_resources` から `fetch` して `<style>` で入れる |
| レイヤー名 | `repogloss-e7b41d` / `-scope`（固定） | `iiyaku-xxxxxxxx-look` / `-scope`（**読み込みごと**） |
| 選択子 | `.iiyaku-icon[data-iiyaku-owner]`（値を見ない） | `.iiyaku-icon[data-iiyaku-owner="iiyaku-xxxxxxxx"]`（**値まで**） |
| 打ち消し（`revert`） | 43 プロパティを列挙して打ち消す | **削除**（与えなければ、打ち消す必要も無い） |

`styles.css` は**雛形**になりました（`RG_LOOK` / `RG_SCOPE` と `[data-iiyaku-owner]` を、走り出しに書き換えてから入れる）。

**実測（v1.8.18）**: ページが同じ名前のレイヤーを先に宣言しても、ページ所有要素は `display:grid` / 赤 / 140×30px / `z-index:5` / 黄背景の**まま**です（レイヤーを使わない書き方・レイヤーだけ・順序を逆に宣言、の3通りとも）。

**副作用として確かめたこと**:

- `permissions` は `storage` のまま。`web_accessible_resources` は**既に辞書で使っている経路**で、`matches` も `https://github.com/*` のまま
- 通信は増えません（`fetch` の相手は `chrome.runtime.getURL` が返す拡張の中の URL 2つだけ。検査で固定）
- 見た目を読めなかったときは**何もしません**（印の丸と "i" は CSS が描くので、読めないまま走ると見えない押せる点だけが並ぶ）
- 配布物は 13ファイルのまま（`styles.css` は配布し続ける）
- 印が出るのは辞書の読み込み後なので、**見た目が付く前に印が出る窓はありません**（両方を `Promise.all` で待つ）

## 7. RG-19-08（P2）合図のたびに、控え全件を測り直していた

**見え方の世代**（`visEpoch`）を入れました。世代が進むのは、DOM の変更・stylesheet の増減・画面の大きさ・CSS の遷移の終わり・利用者の操作・スクロール・暇なときの確認です。控えの候補は最後に見た世代を覚え、**同じ世代なら測り直しません**。

カーソル／フォーカスの合図は、**ページに `:hover` / `:focus` / `:has()` を使う規則があるときだけ**動かします（自分の stylesheet は数えません）。無ければ、カーソルが動いても CSS では何も変わりません——JS で開くメニューは DOM の変更として別経路で届きます。

> ⚠️ **暇なときの確認では、必ず世代を進めます。** ここは属性にも DOM にも出ない変化（`checked` など property だけの書き換え）を拾うための経路なので、世代の門を掛けると永久に気づかなくなります（実測: 2,100件の控えのある見本と、上限でこぼれた候補の見本が、どちらも後から見えた語を見つけられなくなりました。既存の試験2件が落ちて気づきました）。

**残る限界**: `:hover` を使う規則があるページ（GitHub を含む）では、世代はカーソルのたびに進みます。**またいだ回数への比例そのものは残ります。**

## 8. RG-19-07（P2）見分けられない複製 — **直していません**

**判断**: 直すには、印を **closed shadow root** の中へ入れる作り直しが要ります。`cloneNode` は shadow root を複製しないので、複製された宿主は**空の要素になり、押せる点になりません**——構造として断てます。

**なぜ今回やらないか**: 印の同一性・意味づけ（role / aria / tabindex）・見た目・イベントの経路・「まだ使えるか」の判定が全部その上に載っており、E2E の 200 か所以上が `.iiyaku-icon` の属性を直接見ています。**8件の是正と同じ回に混ぜると、どれが原因で何が壊れたのか切り分けられません。** 単独の回で行います。

**残る影響（実測）**: ページが正規の印を複製し、`data-*`・`aria-label`・合言葉の class を**全部**消したうえで `role="button" tabindex="0"` を残すと、幅0の押せる点が1つ残ります。ただし**その形の停止点は、ページが自分だけでも作れます**（こちらの class を使う必要がありません）。監査もこの点を「ページ所有DOMを推測で変更しない撤回判断は正しい」と裁定しています。

## 9. RG-19-09（P2）Windows の E2E が、起動で一過性に落ちる

`Extensions.loadUnpacked` が Windows の runner で 28.4 秒かかり、CDP の上限 20 秒を超えました（run `31811058081`）。同じ配布物に対する前後の run はどちらも 292件全成功で、製品の欠陥ではありません。

**起動段階のこのコマンドだけ**、1回に限って試し直します。置き場所は**呼ぶ側ではなく CDP の送信側**です——呼び出しは 44 か所あり、付け忘れるとその1か所だけが赤いままになります。

- 試し直す前に、**試行回数・経過・失敗の内容・プロセスの状態・CDP の待ち・stderr** を必ず出す
- Chrome が死んでいたら試し直さない
- 2回とも落ちれば、**失敗のまま返す**（緑に化けさせない）
- `continue-on-error` は使わない

製品の assertion の失敗は、この経路を通りません（`STARTUP_METHODS` は `Extensions.loadUnpacked` の1つだけ）。
