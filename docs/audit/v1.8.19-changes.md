## 1. RG-20-01（P1）断定できない候補を、正規の押せる印へ昇格していた

### 何が起きていたか

第18回から、断定できない候補は1周目で見送り、まとめ直しの最後に「まだどこも引き受けていない語」を引き受け直していました。**その2周目は通常の `annotate` を通る**ので、0画素の語が辞書のキーを取り、`tabindex="0"` の正規の印を作っていました。

| 見本 | 実測（v1.8.18） |
|---|---|
| 透明な `url()` filter の語 → 後ろに 1,512画素の語 | 前方に印1・後方0。前方の印は**実際の Tab の順路に入った** |
| 面積0の `polygon(0 0,0 0,0 0)` の中の語 | 語も印も0画素・印の5点すべてが **BODY**・それでも Tab の順路に入った |
| ちょうど45°・止まれない吸い寄せ | 同じ形 |

### 直したこと

**2周目を廃止しました。** 断定できない候補は `false` と同じに扱い、**節点は控えへ残します**。ページの状態が変わって断定できるようになれば、控えの見直しがそこで拾います。

> **⚠️ 代償を明記します。** 実際には見えているのに断定できない語（解けない `filter` の `url()`・ちょうど45°・未対応の `clip-path` の中など）は、ページに他の出現が無ければ**説明されません**。「見えない押せる点を作らない」ほうを取りました。

> **⚠️ 監査の受入条件のうち1つは、この方針では満たせません。** 「透明な `url()` filter → 可視な `url()` filter の順で、可視側に付く」は、SVG filter の中身を解かないと区別できません。実測でも**どちらにも付きません**。試験で固定したのは「断定できない候補が、確実に見える語からキーを奪わない」という不変条件のほうです。

## 2. RG-20-02（P1）解けない `clip-path` を「制限なし」として扱っていた

`shapeHitTest` が解けるのは `circle()` / `ellipse()` / 角丸つき `inset()` だけで、それ以外は null を返します。その null を「形の制限は無い」として通していました。

実測（v1.8.18）: 面積0の `polygon(0 0,0 0,0 0)` の中の語は0画素、印も0画素で5点すべてが BODY なのに、確実に見えるものとして扱われていました。

解けないときは**断定しない**ようにしました。3D・`perspective` で形を解けない場合も同じ経路へ送ります。

> **⚠️ ここで私は12件の対照を落としました。** 「解けない形」と「**外接矩形で足りる形**」を一緒くたにしたためです。角を丸めていない `inset()` と、参照ボックスだけの `clip-path`（`clip-path: content-box` など）は**矩形そのもの**で、外接矩形の交差だけで正しく決まります。いまは `shapeHitTest` が `'rect'` を返して区別します。

## 3. RG-20-03（P1）印の実測が、不透明度・visibility・重なりを見ていなかった

矩形・切り取り・到達性・形しか見ていませんでした。

| 見本 | 実測（v1.8.18） |
|---|---|
| ページ CSS の `.iiyaku-icon{opacity:0!important}` | 印は `opacity:0` のまま `tabIndex:0` で Tab の順路に入った |
| 不透明な `position:fixed` が印を全面的に覆う | 印の画素が 96 → 0、5点すべてが覆いを返しても合格していた |

印自身の `visibility` / `display` / `opacity` / `content-visibility` / `checkVisibility` に加えて、**当たり判定で覆われていないか**を見るようにしました。

> **⚠️ ここでも私は対照を落としました（5件）。** 「祖先が最前面に出る」のを覆いと数えたためです。印がスクロールで送られた先にあるとき、その点で返るのは**入れ物（＝印の祖先）**になります。覆いと呼べるのは、印とも印の祖先とも関係のない要素が前に出ているときだけです。
>
> さらに、当たり判定は「**いまスクロールを動かさずに見えている印**」にだけ当てるようにしました（`visibleNow`）。送られた先の座標で当たり判定をすると、そこに描かれている別のものが返ります。

## 4. RG-20-04（P1）mask を要素全体で判定し、語の位置を見ていなかった

gradient の中に1つでも不透明／明るい色があれば、層全体を残る側にしていました。

| 見本 | 実測（v1.8.18） |
|---|---|
| 左55%が透明な alpha mask | 語は0画素なのに印1 |
| 左55%が黒の luminance mask | 同じ |
| `match-source` が指す SVG の `mask-type="luminance"` の黒い mask | 同じ |

**一様でない gradient は断定しない**ようにしました（gradient の値は場所で変わるため）。断片の URL（`url(#id)`）は SVG の `<mask>` を指しうるので、こちらも断定しません。画像の URL は今までどおりです（第17回 RG-17-04 の対照＝不透明な画像の層は残る、を壊さないため）。

## 6. RG-20-06（P2）CSSOM で足された hover 規則に気づかなかった

`insertRule()` は DOM に何も出さないので、`<head>` の見張りでは気づけません。

実測（v1.8.18・本物のマウス）: 起動後に `insertRule` で足した `:hover` メニューは、300ms・600ms の時点で印0、1,200ms でようやく1（＝2秒ごとの確認まで待たされた）。対照（最初から規則がある）は 300ms で1。

stylesheet の**形の指紋**（枚数と規則の数）を見て、変わっていれば判定を作り直します。

## 8. RG-20-08（P2）見分けられない複製 — **直していません**

第19回から続く持ち越しです。印を **closed shadow root** の中へ入れる作り直しが要ります（`cloneNode` は shadow root を複製しないので、複製された宿主は空の要素になり押せる点になりません）。

印の同一性・意味づけ（role / aria / tabindex）・見た目・イベントの経路・「まだ使えるか」の判定が全部その上に載っており、E2E の 200 か所以上が `.iiyaku-icon` の属性を直接見ています。**9件の是正と同じ回に混ぜると切り分けられません。**

第20回監査も「ページ所有DOMを推測で変更しない撤回判断は妥当。v1.8.18 を HOLD する限り分離対応は可能」と裁定しています。ただし**ストア提出前には閉じる必要がある**とも書かれています。

## 9. RG-20-09（P2）hover 規則のあるページでの、控え全件の評価

`:hover` が当たるのはポインタの祖先の連なりだけなので、**その連なりが同じなら CSS が作る見え方は同じ**です。擬似クラスの状態を覚え、同じ状態でひと回り終えていれば回さないようにしました。DOM・stylesheet・画面が変われば記録は捨てます。

**実測（隔離された世界の中で `checkVisibility` を数えた・陽性対照つき・本物のマウス）**:

| 見本 | 合図 | 飛ばした |
|---|---:|---:|
| 2,000候補・hover 規則あり・10移動 | 24 | **10**（42%） |

⚠️ **総回数は変わりませんでした**（v1.8.18 も v1.8.19 も 24,024回）。この規模では、**2秒ごとの確認**と、カーソルの間引き（最大300ms）が支配的だからです。**またいだ回数への比例そのものは残ります**（§7 の19番）。仕組みは動いていますが、端から端までの数字には出ませんでした。
