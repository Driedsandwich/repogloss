## 1. RG-22-01（P1）退役した印の、shadow の中の押せる実体を失効させていなかった

### 何が起きていたか

v1.8.20 で単独の印を closed shadow root へ移し、「`cloneNode` は shadow root を複製しない」ことで**見分けられない複製**を閉じました。しかし、**複製されないことと、退役した元が失効することは別の不変条件**でした。

`retireGloss()` は、ページがその節点に本文を入れていた場合、light DOM 側の class・data 属性・操作性だけを外して手を引きます（ページの持ち物を壊さないため）。**shadow の中の button と説明文には触れていませんでした。**

反例（ページが退役した印を本文の入れ物として使い回す）:

```html
<button id="start">start</button>
<p id="first">A branch first.</p>
<p id="second">A branch second.</p>
<script>
setTimeout(() => {
  const host = document.querySelector('#first .iiyaku-icon');
  host.id = 'reused';
  host.textContent = 'PAGE CONTENT';
}, 200);
</script>
```

| 実測（v1.8.20 の実物） | 値 |
|---|---:|
| 「「branch」の解説」という名前の押せる button | **2個**（どちらも `focusable: true`） |
| 使い回された節点の Tab 停止点 | **1**（実際に止まる） |
| light DOM の姿 | `<span class="" id="reused">PAGE CONTENT</span>`（自分の名札は消えている） |

### 直したこと

`deactivateShadowIcon(host)` を足し、**所有を取り消すのと同じ場所**（`retireGloss` の中）で呼びます。

- 取り除く**前に**押せなくする（`disabled` / `tabIndex = -1`）。取り除きに失敗しても停止点は残らない
- `aria-label` / `aria-describedby` / `aria-expanded` を失効し、button と説明文を shadow root から取り除く
- `iconButton` / `iconDesc` の所有も消す
- ⚠️ **DOM に繋がっているかを条件にしない**。ページが外して持っていた印をあとから戻すと、中の button が生き返るため
- ⚠️ **`<slot>` は残す**。外すとページが入れた本文が描かれなくなる（第21回で一度踏んだ）

### 直したあと（同じ見本）

| 項目 | v1.8.20 | v1.8.21 |
|---|---:|---:|
| 押せる解説の数 | 2 | **1** |
| 使い回された節点の Tab 停止点 | 1 | **0** |
| `PAGE CONTENT` の表示 | 残る | **残る**（変えていない） |
| 外して戻したあとの押せる解説 | — | **1**（生き返らない） |

## 2. RG-22-02（P1）ページ由来の変数が shadow の中まで継承し、印が 0 画素になった

### 何が起きていたか

custom property は**shadow の境界を越えて継承**します。印の色は GitHub のテーマに合わせるため `--fgColor-accent` などを読んでいるので、ページが前方の段落へ

```css
#first { --fgColor-accent: transparent; --color-accent-fg: transparent; }
```

を置くと、その値が shadow の中の button まで届き、字も枠も透明になります。

| 実測（v1.8.20 の実物） | 値 |
|---|---:|
| 印の矩形（14×14＝196画素）の、白でない画素 | **0** |
| 対照（変数をいじらない同じ形） | 129 |
| その印の Tab 停止点 | **1**（見えないのに止まる） |
| 後方の読める同じ語 | **0**（説明されない） |

### 直したこと

**測ってから、shadow の中だけで塗り直します。**

1. shadow 用の CSS を `var(--rg-fg, var(--fgColor-accent, …))` の形にする
2. `ensureShadowPaint(host)` が、ページのテーマ色で**実際に塗れるか**を computed style で測る
3. 塗れないときだけ `--rg-fg` を**button のインライン**へ書く（closed shadow root の中なのでページからは触れない）。値はページの本文の色 → それも透明なら `CanvasText`
4. `iconIsPainted()` が、host ではなく**押せる実体**（`focusTargetOf`）の塗り・大きさ・`visibility` を見る

塗れているあいだは何も書かないので、**ふだんのテーマ追従は変わりません**。ページ側の値が変わったときだけ測り直します。

> **⚠️ `@property { inherits: false }` は使えません。** 登録は**文書ぜんぶ**に効くので、ページ自身が使っている `--fgColor-accent` の振る舞いまで変えてしまいます。

### 直したあと（同じ見本）

| 項目 | v1.8.20 | v1.8.21 |
|---|---:|---:|
| 印の白でない画素（透明な変数の側） | **0 / 196** | **104 / 196** |
| 対照（変数をいじらない同じ形） | 129 / 196 | 104 / 196 |
| 前方／後方の印 | 1 / 0 | 1 / 0（説明を捨てていない） |

⚠️ **対照の値も変わっています**（129 → 104）。§7 で印の絵を light DOM から shadow の中へ寄せ、
**輪が1本になった**ためです。v1.8.21 では、透明な変数を置かれた側と置かれていない側が
**同じ画素数**になりました（どちらも 104）——つまり見た目の差がありません。

## 3. RG-22-03（P1）`pointer-events: none` の覆いが当たり判定に映らない

### 何が起きていたか

`pointer-events: none` の箱は hit testing から**外れます**。`elementFromPoint` はその下にあるものを返すので、印は「最前面」に見えます。v1.8.20 はこれを**既知の限界**として、覆いを主張しない側へ倒していました。

| 実測（v1.8.20 の実物） | 値 |
|---|---:|
| 覆う前の印の画素 | 129 / 196 |
| 不透明な白い箱（`pointer-events:none`・`z-index:2147483647`）で覆ったあと | **0 / 196** |
| 5点の `elementFromPoint` | すべて**印**を返す |
| 前方／後方の印 | 1 / 0（0画素の印が正規のまま） |

### 採らなかった道具

**IntersectionObserver v2（`trackVisibility`）は使えません。** 遮蔽まで見てくれる API ですが、実測では**覆いが無くても**この印を `isVisible: false` と答えました。同じ実行で、ふつうの `<div>` と `<button>` は `true` です——環境の問題ではなく、この印が対象外と判定されています。覆いの有無で答えが変わらないので、判別に使えません。

**全要素を歩いて集める形も採りませんでした。** 実測で 10,000要素あたり **6〜13ms**。印の実測は変更のたびに走るので、そこへ足せません。

### 直したこと

覆いの候補を、**宣言のある場所から引きます**。

1. `pointer-events: none` を宣言している**規則の選択子**を集める（stylesheet の走査。指紋が変わったときだけ取り直す）
2. `style` 属性にそう書いてある要素を足す
3. `pointer-events` は継承するので、当たった要素の**中**も候補に入れる
4. 読めない stylesheet が1枚でもあれば、見落とすので**全要素を歩くほうへ落とす**

そのうえで、**断定できる覆いだけ**を数えます——地の色が不透明・透けていない（祖先まで見る）・位置指定がある・重なり順で印より前（`z-index > 0`、または指定が無ければ後から来たほう）。

判定は**点ごと**（印の矩形の5点）に行うので、部分的な覆いでは残りの点が露出と数えられます。

宣言が1つも無いページでは、走査そのものが起きません。

### 直したあと（同じ実行・対照つき）

| 見本 | 前方 | 後方 | 意味 |
|---|---:|---:|---|
| 不透明な覆い（`pointer-events:none`） | **0** | **1** | 見つけて、後方の読める語へ移った |
| 透明な覆い | 1 | 0 | 落としすぎていない |
| 部分的な覆い（4px 幅） | 1 | 0 | 落としすぎていない |
| ふつうのスクロール枠 | 1 | 0 | 覆いと誤認していない |

覆われた印の Tab 停止点は **0**。覆いを置いたあと、同じ画面の矩形の白でない画素は **0**（覆う前は 104）。

> **⚠️ 残る限界。** **印自身が `pointer-events: none` にされた場合**は、当たり判定では何も言えないので覆いを主張しません。画像や gradient で塗った箱、重なり順を推し量れない箱も「覆いではない」側へ倒します（落としすぎると、ふつうのページの語が説明されなくなるため）。**「印の見え方を完全に検証している」とは主張しません。**

## 4. RG-22-04（P2）CSSOM の宣言だけの書き換えに気づかない

### 何が起きていたか

選択子も規則の数も変えずに `cssRules[0].style.display` を `none` → `inline` にすると、DOM にも属性にも event にも何も出ません。

| 実測（v1.8.20 の実物） | 印 |
|---|---:|
| 変える前（`display: none`） | 0 |
| 650ms 後（`display: inline` になっている） | **0** |
| 2秒ごとの確認のあと | 1 |

### 採らなかった道具

監査は「指紋へ宣言の `cssText` を含める」ことを求めていましたが、**費用を測ってから見送りました**。

| やり方（10,000規則） | 1回の時間 |
|---|---:|
| 選択子だけ（v1.8.20 の現行） | 2〜8ms |
| ＋ 宣言の**本数** | 0.6〜1.4ms（本数を数えるだけ） |
| ＋ 宣言の **`cssText` を hash** | **23〜31ms** |
| 参考: `cssText` を**作るだけ**（hash しない） | 20〜27ms |

費用の主は文字を舐める分ではなく **`cssText` を作る分**なので、安い書き方がありません。この指紋は**カーソルの合図ごと**（120ms の窓）に取るので、そこへ 25ms を足すと、カーソルを動かしているあいだ 20% を使うことになります。

しかも指紋は「どこかが変わった」としか言えません。

### 直したこと

**控えの見え方そのものを、短い周期（400ms）で測り直します。** CSSOM に限らず、合図の出ない変化すべてに効きます。

- 見に行く相手（控え）が無い／画面が見えていない／使いすぎ、のときは何もしない
- ⚠️ **まとめ直し（`runBatch`）を予約しない**。ここは周期の見張りであってページの変更ではないので、予約すると「1回のページ変更で、まとめ直しは1回」を守っている検査が壊れる（実測: 1 のはずが 3）
- ⚠️ **`dropStates()` を呼ばない**。擬似クラスの memo を消すと、次のカーソルの合図が全件を回し直す（実測: `checkVisibility` が 3,542 → 18,108 回）
- ⚠️ **間隔は控えの件数に合わせて空ける**（1秒あたり 1,250候補を上限、最大 2,000ms）。一定間隔だと件数に比例して CPU を食う（実測: 5,000件で 35,042 → 46,844 回）

指紋には宣言の**本数**だけを足しました（足し引きされた宣言に気づくため。0.6〜1.4ms）。

### 直したあと

宣言を書き換えてから **600ms 以内**に印が付きます（実測）。性能は §8。

## 5. RG-22-05（P2）`:target` と `:focus-visible` を合図にしていない

### 何が起きていたか

| 見本（v1.8.20 の実物） | 600ms 後 | 2秒後 |
|---|---:|---:|
| `location.hash` を変えて `:target` で開くメニュー | 印 **0** | 1 |

`hashchange` / `popstate` を購読しておらず、**フォーカスの相手が変わらない**ので `focusin` も来ません。

鍵に入れたので、既存の間引き・使いすぎの門・範囲の絞りがそのまま効きます。

### 直したあと

どちらも **600ms 以内**に印が付きます（実測）。

## 6. RG-22-06（P2）ページが合成した click で、恒久の設定を書き換えられた

### 何が起きていたか

切替ボタンは light DOM に居るのでページから参照でき、`.click()` や `dispatchEvent(new MouseEvent('click'))` で押せていました。

| 実測（v1.8.20 の実物） | 結果 |
|---|---|
| ページ側の script から `.click()` | 「解説 ON」→「**解説 OFF**」 |
| **別のタブを開く** | そのタブも「解説 OFF」＝**保存まで届いていた** |
| 合成 `MouseEvent` を dispatch | もう一度切り替わる |

### 直したこと

```js
btn.addEventListener('click', async event => {
  if (!event.isTrusted) return;
  …
});
```

ブラウザが起こした操作だけ `isTrusted` が真になります。

> ⚠️ **この門は設定を変える経路だけ**に掛けます。受け身の合図（カーソル・フォーカス・スクロール）へ広げてはいけません——合成された変化でも「見えるようになった」ことは本当に起きているためです。検査でも、`isTrusted` の出現がこの1か所だけであることを確かめています。

### 直したあと（同じ実行・対照つき）

| 操作 | 表示 | 保存（別タブ） |
|---|---|---|
| ページからの `.click()` | 解説 ON のまま | ON のまま |
| 合成 `MouseEvent` | 解説 ON のまま | — |
| **本物のマウス click** | **解説 OFF へ** | — |
| **Enter / Space** | **切り替わる** | — |

## 7. （自分で発見）v1.8.20 の印は、輪が二重で "i" が箱の外へはみ出していた

RG-22-02 を直す途中で印を **8倍に拡大して撮影**したところ、v1.8.20 の単独の印が次のようになっていました。

- light DOM の host が、自分の枠（14×14）と `::after` の "i" を**まだ描いていた**
- shadow の中の button が、**もう1つの輪**（8×11）を描いていた
- host は `display: inline-flex` なので、`::after` の "i" が flex の2つ目の項目として**右へ押し出され**、箱の外へはみ出していた

原因は2つです。①shadow へ移したときに light DOM 側の絵を消し忘れた。②shadow の button に `width: 1.15em` と `font-size: .78em` を light DOM の規則からそのまま写したので、host に既に効いている `.78em` と**二重に掛かって**縮んだ。

### 直したこと

- shadow root を持つ印（`:not([data-iiyaku-for]):not([role])`）は、light DOM 側で**枠も "i" も描かない**（`border-width: 0` / `content: none`）
- 印の "i" は shadow の中の `button::after` が描く
- button は `width: 100%` / `height: 100%` / `font: 700 1em/1 …` で **host いっぱい**に広がる

**画素と意味づけだけを測っていて、拡大して見ることをしていませんでした。** 監査もここは指摘していません。E2E に「light DOM の host は枠も "i" も描かない」「button が host と同じ大きさ」を固定しました。

## 8. 性能（2026-08-15・同じ見本で v1.8.20 と並べて実測）

計測器は**隔離された世界の中**、カーソルは**本物のマウス**、陽性対照つき。控えは `latentPage(n)` に `:hover` 規則を1つ足したもの。

**カーソルを10回動かしたとき**の `checkVisibility` 呼び出し回数:

| 控えの候補数 | v1.8.20 | v1.8.21 |
|---:|---:|---:|
| 500 | 3,542 | 7,554 |
| 2,000 | 14,042 | 15,894 |
| 5,000 | 35,042 | **15,018** |

**何もしないで4秒待ったとき**:

| 控えの候補数 | v1.8.20 | v1.8.21 |
|---:|---:|---:|
| 500 | 2,016 | 6,028 |
| 2,000 | 8,016 | 8,014 |
| 5,000 | 20,016 | 15,012 |

**実時間（同じ待ち時間に対する経過。小さいほど画面が詰まっていない）**:

| 場面 | v1.8.20 | v1.8.21 |
|---|---:|---:|
| カーソル・5,000候補 | 6,043ms | **4,131ms** |
| 待つだけ・5,000候補 | 5,299ms | **4,009ms** |

- 控えが少ないときは、**測り直す回数が増えます**（400ms ごとに見に行くため）。これは「合図の出ない変化を 2秒でなく 600ms で拾う」ことの代償です。
- 控えが多いときは、**間隔を空ける**のと使いすぎの門が効いて、v1.8.20 より少なくなります。
- 1秒あたりに見る候補数は **1,250 件で頭打ち**にしてあるので、ページが大きくなっても増え続けません。
- 実時間はどの場面でも v1.8.20 より短くなりました。
