## 1. 指摘ごとの対応

### RG-8-01 — 最初の印が消えると、既にある2番目の候補へ引き継がれない（P1）

**何が起きていたか。** 「同じ語はページで最初の1回だけ」を実現するため、既に説明済みの語を含む節点も**処理済み**として記録していた。その記録が永久に残るので、最初の印を含む場所がページから消えても、2番目の候補は二度と選ばれない。

実測（v1.8.6・`branch` を2か所に置き、最初を削除）:

| 段階 | `#first` | `#second` | ページ全体 |
|---|---:|---:|---:|
| 初期 | 1 | 0 | 1 |
| `#first` を削除＋無関係ノード追加 | — | **0** | **0** |
| さらに URL 変更＋全体走査 | — | **0** | **0** |

**読める語がページに残っているのに、説明が0回になる。** 仕様ではなく不具合。

**直し方（監査の推奨A: 世代つき handled）。**

```text
handled: WeakMap<Text, generation>    // 「いつ処理したか」を持つ
generation: 整数                       // 正規の印が退役したときだけ進める
```

ふつうの変更では世代を進めないので、走査の費用は変わらない。退役は稀なので、そのときだけ全体から選び直す（`reselect`）。

**証拠。** E2E「印が居なくなったら、既にある候補へ引き継ぐ」4件 — 2番目へ移ること／**隠れている候補（`display:none`）は選ばず**その次の読める候補へ移ること／URL 変更でも同じこと／10往復しても印が1個で本文が変わらないこと。

### RG-8-02 — 語と印の対応が壊れても、印だけを見て後続を抑止する（P1）

**何が起きていたか。** `usableGloss` は印が DOM にあり可視で到達可能かだけを見ていた。記録した語がまだそこにあるかを見ていない。

実測（v1.8.6）:

| 壊し方 | 結果 |
|---|---|
| 語の Text node だけを削除 | 印が語の無い場所に残り（1個）、後から現れた本物の `fork` は **0個**に抑止された |
| 語と印のあいだへページが節点を挿す | 印が `A merge` ではなく `PAGE_INSERT` の直後に位置した |

**直し方。** 記録全体の整合を毎回確かめる（`isCoherent`）。

```text
icon.isConnected / termNode.isConnected
icon.parentNode === 記録した parent / termNode.parentNode === 記録した parent
termNode の記録位置に、記録した語がそのまま残っている
icon.previousSibling === termNode
hosted なら、その入口 ID を引いていま返るのが記録した入口である
```

食い違ったら記録を退役させ、RG-8-01 の選び直しを起こす。**ページ側の節点は動かさない** — 自分の印を外し、選び直しで語の直後へ入れ直す。これで結果的に印は語の直後へ戻り、ページが置いた節点はそのまま残る。

`removedNodes` を伴わない変更（語だけの書き換え、あいだへの挿し込み）でも起きるので、**ノードが増えただけの変更でも**記録を数え直す（最大61件・DOM の読み取りだけでレイアウトは起こさない）。

**証拠。** E2E 5件 — 語だけ削除／語の書き換え／あいだへの挿し込み（ページ節点の同一性・中身・位置を維持し、印は語の直後）／別の親へ移動／選択範囲（逆向き・印跨ぎ）の維持。

### RG-8-03 — 切り取りの判定に取りこぼしがあり、`display:contents` では落としすぎ（P1）

**何が起きていたか。** 決まった書き方（`rect(0 0 0 0)` と `inset(50%)`）だけを文字列で照合していた。

実測（v1.8.6）:

| 形 | 隠れている側 | 後ろの読める側 | 正しい答え |
|---|---:|---:|---|
| `position:absolute; clip:rect(5px,5px,5px,5px)` | **1** | 0 | 0 / 1（面積は0） |
| `clip-path:inset(100%)` | **1** | 0 | 0 / 1 |
| `display:contents; clip-path:inset(50%)` | **0** | 1 | 1 / 0（箱が無いので効かない） |

**直し方。** 文字列の照合をやめ、**面積で決める**。

- `rect(top,right,bottom,left)` を4値に解き、`right <= left` か `bottom <= top` なら面積0。`auto` が混ざれば断定しない。`position:absolute|fixed` の条件は維持
- `inset()` を1〜4値へ展開し、縦か横の合計が100%以上なら面積0。長さと百分率が混ざると箱の大きさ抜きに決められないので断定しない
- **`display:contents` の要素自身の `clip` / `clip-path` は適用しない**（箱を作らないので効かない）。箱を持つ先祖の連なりは従来どおり見る

**証拠。** E2E「面積で判定する（5種）」＝ `rect(5px,5px,5px,5px)` 0/1・`rect(10px,8px,10px,3px)`（fixed）0/1・`inset(100%)` 0/1・面積の残る `rect(0,200px,40px,0)` は1・`inset(10%)` は1・`display:contents` 自身の `inset(50%)` は1。

**対照はブラウザの当たり判定で取る**（こちらの式の言い換えにしない）。文字が描かれている場所を `elementFromPoint` で突き、面積0のものには当たらず、面積の残るものと `display:contents` のものには当たることを見る。

> 対照を書くときに2つ間違えた。①要素の箱の左端 4px を突いていたので、`inset(10%)` では**切り取られた余白**を突いていた（部分的な切り取りは主張の対象外なので、この形は当たり判定から外した）。②`hit.contains(el)` を「当たった」に数えていたため、全面を切り取ると `body` が返って**当たったことになっていた**。文字の範囲で測り、`el.contains(hit)` だけで数えるよう直した。
>
> なお `caretRangeFromPoint` は `clip-path` を無視して切り取られた文字にも当たる（実測）ので、可視の判定には使えない。

### RG-8-04 — 複製された印と入口 ID を、自分のものとして扱ってしまう（P2）

ページ側が注記済みの領域を `cloneNode` で複製すると、印も入口 ID もそのまま複製される。実測では、同じ入口 ID を持つ要素が **2つ**になり、その ID で入口を引くと複製側が返りうる状態になった。同じ語の印もページに2つ出た。

**直し方。** 自分が作った印と入口を `WeakSet` で持ち、追加された領域を走査する**前に**、所有していない `.iiyaku-icon` と、自分の UID 形式の `data-iiyaku-trigger` を取り除く。触るのは自分のものだけで、ページ側の属性・本文には手を出さない。

**証拠。** E2E 2件 — 単独の印とリンクの中の印の両方を複製し、複製側 0・入口 ID の重複 0・複製側の本文が無傷であること。**複製したあとに元を消すと、複製側へ正規の印が1つ移る**こと。
