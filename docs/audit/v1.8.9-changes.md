## 1. 指摘ごとの対応

### RG-10-01 — 見張る属性を絞り込んでいた（P1）

**実測（v1.8.8）**、3通りとも「隠れた側に印が残り、後ろの読める語は0個」だった。

| 何をしたか | v1.8.8 |
|---|---|
| `input.type = 'hidden'`（label の control が到達不能になる） | label に印1・後ろ0 |
| 任意の `data-state` で `display:none` | 元の場所に印1・後ろ0 |
| `checked` プロパティ＋`:has()` で祖先を隠す | 元の場所に印1・後ろ0 |

`attributeFilter` を使う限り、列挙していない属性の変化は通知されない。どの属性が見え方に効くかは CSS 次第なので、一覧では追いつけない。

**直し方。** 属性の絞り込みを撤廃した。加えて、利用者の操作（`input` / `change` / `click`）も合図にする。

**属性にも DOM にも出ない変化**（`checked` のようなプロパティだけの書き換えを、操作なしに行う場合）は、どの合図にも乗らない。ここは `requestIdleCallback` による**暇なときの確認**（2秒に1度・画面が見えていないときと記録が無いときは何もしない）でしか拾えない。**即座ではない**という制約は残る（実測: 約2.5秒で移った）。

**証拠。** E2E — `type=hidden` と `data-state` は即座に後ろへ移ること。属性を100回連打しても印は常に0か1で、連打をやめれば数が動かなくなること。

### RG-10-02 — 子が増えただけでも祖先が消える（P1）

`:has()` を使えば、子を1つ足すだけで祖先が `display:none` になる。v1.8.8 は「増えただけなら見え方は変わらない」として、追加だけの変更では見え方を確かめ直していなかった。

**実測（v1.8.8）**: `.hider` を1つ append すると `#first` は `display:none` になったが、印はそこに残り、`#second` は 0 個。

**直し方。** childList の追加でも深く確かめる。記録は辞書のキーの数（61）で頭打ちなので、確かめ直しの費用は上限が決まっている。

### RG-10-03 — DOM の変更として出ない合図（P1）

3経路とも再現した。

| 経路 | v1.8.8 |
|---|---|
| `opacity` の transition が終わって 0 になる | 透明になった印がそのまま残る |
| 画面幅 900→500 で media query が入れ替わる | 消えた側に印が残る |
| `<head>` へ `<style>` を足して隠す | `body` しか見張っていないので気づかない |

**直し方。** `transitionend` / `transitioncancel` / `animationend` / `animationcancel`、`resize` / `orientationchange`、`<head>` の監視を足し、**すべて1つの予約口へ集約**した。1回のまとめ直しでやることは、複製の除去・整合の確認・見え方の確認・世代を進める・全体の選び直しが**それぞれ最大1回**である。

**証拠。** E2E — 遷移・画面幅（往復）・head の stylesheet の3つで、後ろの読める語へ移ること。

> **stylesheet を外しても、印は戻らないのが正しい。** 移った先が読めている限り、その語は説明済みだからである（戻すと同じ語の印が2つになる）。E2E でもそう固定した。

### RG-10-04 — OFF 中の複製と、合言葉を失った複製（P2）

**実測（v1.8.8）**: OFF のあいだに注記済みの領域を複製して ON へ戻すと、正規の印と複製の印が**2つ**残った。複製から `data-iiyaku-owner` を消した場合も、見た目は印のまま残った。

**直し方。** ON へ戻すとき、走査より前に**ページ全体から複製を取り除く**。合言葉を消された複製は「自分のものではない」ので取り除かない（ページの持ち物を消さない）が、**CSS の側でも合言葉を要求する**ようにした（`.iiyaku-icon[data-iiyaku-owner]`）。合言葉が無ければ丸も "i" も描かれない。

**証拠。** E2E — OFF 中の複製は ON 復帰で消え、印は1つ。合言葉を消した複製は**DOM に残るが**、`display` が `inline-flex` でなく、枠線も `::after` の "i" も出ないこと。

### RG-10-05 — 所有は、変更した主体の証明ではない（P2）

**実測（v1.8.8）**: ページ側が正規の印へ `style="display:none"` を書くと、見えない印が「説明済み」として残り、後ろの読める語が抑止された。`MutationRecord` に変更の主体は載らないので、「自分の要素だから自分の変更」という推し量りが成り立たない。

**直し方。** 自分が書くつもりの「要素 + 属性名 + 値」を控えておき（`expectedAttrs`）、**その3つが完全に一致する変更だけ**を自分の仕業として無視する。自分が書く属性はすべてこの経路を通す（`verify.mjs` が、素の `setAttribute` が残っていないことを陽性対照つきで検査する）。

**証拠。** E2E — ページ側が印を隠すと、その印は退役し、**見える新しい印に置き換わる**（合計1・見える1・`style` 付き0）。

### RG-10-06 — `clip-path` の文法（P2）

**実測（v1.8.8）**、どちらも隠れた側に印が付き、後ろの可視語は0個だった。

| 書き方 | computed 値 |
|---|---|
| `clip-path: inset(50%) content-box` | `inset(50%) content-box` |
| `clip-path: ellipse(0 closest-side)` | `ellipse(0px closest-side)` |

**直し方。** `<basic-shape> || <geometry-box>` として、末尾の参照ボックスを分離する。百分率はその箱の**実寸**へ換算する（`content-box` は border と padding を引いた内側）。`ellipse` の半径にキーワードが混ざっても、**片方が 0 なら面積は 0**として扱う。

**既知の制約は維持**: `calc()` を含む値、`polygon()`、`path()`、`shape()` は解かない（可視として扱う）。

### RG-10-07 — 大規模な属性切替の性能（P2）

監査は 2,500段落の祖先 class を切り替える合成試験で、v1.8.8 が v1.8.7 より **+45.75 ms（中央値）** 遅いと報告した。

**直し方は2つ。**

1. **全体走査と、変更箇所の走査を重ねない。** 退役が起きて全体を選び直すときは、変更のあった場所を別に走らない（同じ枝を二度歩かない）
2. **辞書に当たらない節点を処理済みにする。** 以前は、辞書語を含まない節点を毎回 `closest(SKIP)` と正規表現に掛け直していた。文字が変わらない限り答えは同じなので、一度で済ませる（文字が変わったときは `characterData` の合図で記録を消す）

**実測（実行順を交互に反転して4組）:**

| 版 | 中央値 | 各組（ms） |
|---|---:|---|
| v1.8.7 | 16.5 ms | 20.3 / 17.2 / 15.1 / 15.7 |
| v1.8.8 | 26.8 ms | 26.4 / 26.9 / 26.7 / 26.9 |
| **v1.8.9** | **21.6 ms** | 21.8 / 21.0 / 21.5 / 21.7 |

**v1.8.9 は v1.8.8 より4組すべてで速い**（差 −4.6 / −5.9 / −5.2 / −5.2 ms）。50ms を超える long task は3版とも 0 件。

> **v1.8.7 との比較は同じ土俵ではない。** v1.8.7 はこの属性変更に**反応しない**（記録を確かめ直さない）ので、その分だけ速く見える。仕事をしたうえでの比較は v1.8.8 対 v1.8.9 である。監査の数字（+45.75 ms）とこちらの数字（+10.4 ms）が違うのは、合成ページと計測方法が違うためで、**向きは一致している**。
>
> **計測を一度間違えた。** マイクロタスクを1つだけ待つ形にしたところ、v1.8.9 の予約はさらに後のマイクロタスクで走るため **0 ms** と出た。タスク境界まで待つ形へ直している。
